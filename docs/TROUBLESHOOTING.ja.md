## 1. ノードが `/api/v1/nodes` に表示されない

**症状:** ESP32-S3 ノードが WiFi に接続し LED が点滅しているが、サーバーに CSI フレームが届かない。`/api/v1/spatial/nodes` にノードが表示されない。

**根本原因:** USB 書き込み後、ノードが不完全な状態になり、WiFi 接続は成功しても UDP CSI 送信が暗黙的に失敗することがあります。SoftAP と mDNS スタックは初期化されますが、CSI コールバックが発火しません。

**修正方法:** ノードの電源を再投入（USBを抜き、2秒待って再挿入）します。解決しない場合はシリアル経由で DTR リセットを送信します： `python -m serial.tools.miniterm --dtr 0 COMx 115200` を実行後に Ctrl+C。

**予防策:** ファームウェア 0.8.0 以降には、30秒間 CSI フレームが検出されない場合に自動的にソフトウェアリセットを呼び出すウォッチドッグが含まれています。

## 2. 人数カウントが 1 に固着する

**症状:** 部屋に何人いても `estimated_persons` が常に 1 を返す。

**根本原因 (ADR-044):** 以下の複数の要因が絡み合っていました：
1. `score_to_person_count` の上限が 3 に固定されていた
2. `fuse_multi_node_features` が加算ではなく `.max()` を使用していたため、N個の同一読取が 1 つに潰れていた
3. 4箇所の `.max(1)` クランプにより、無人時でも最小値が 1 に強制されていた
4. `field_model.estimate_occupancy` が `.min(3)` で制限されていた
5. 正規化の頭打ち（動的な p95 ではなくハードコードされた閾値で除算していた）

**適用された修正 (Waves 1-3):**
- Wave 1 (`9cc5f604`): 上限を 3→10 へ変更、`.max()` から加算/3 集約へ変更、`.max(1)` クランプの緩和
- Wave 2 (`306f1262`): RollingP95 適応正規化、field_model 30秒自動キャリブレーション（**空部屋測定（ベースライン校正）**）の導入
- Wave 3 (`c3df375a`+`0d4bfb09`+`6ac70ddf`): クラスタリング・トモグラフィ判定の改良

## 3. 心拍数 / 呼吸数（バイタル測定（心拍・呼吸））のブレ・ジッター

**症状:** 心拍数（HR）と呼吸数（BR）の測定値がフレーム間で激しく変動する。

**根本原因 (ADR-045):** 複数の ESP32 ノードがそれぞれ独自にバイタルを計算しており、サーバー側が「最後に来たデータを上書き（last-write-wins）」していたため、ノードごとの測定値が交錯していました。

**適用された修正 (`46fbc061`):** ベストノード選択ロジックの導入。各ノードの**バイタル測定（心拍・呼吸）**データをメディアンフィルタ + EMA で平滑化し、最も信頼度が高いノードの測定値を採用するように変更。

## 4. 信号品質が常に 50% と表示される

**症状:** ダッシュボードの信号品質ゲージが常に約 50% で固定される。

**根本原因:** 信号品質の値が実際の CSI データから計算されておらず、ハードコードされたダミー値であったため。

**適用された修正:** ADR-044 Wave 2 にてプレースホルダー値を RollingP95 適応正規化（**電波変動量（動作強度）**の動的スケーリング）に置換し、UIの改善 pass (`b2070ab4`) によりノードごとのリアルタイム表示へ更新されました。

## 5. ダッシュボードが 2-4 秒ごとにフリーズする

**症状:** 空間表示やダッシュボードがフリーズして再接続を繰り返す。

**根本原因:** クライアント側の処理が遅れた際に WebSocket 放送チャネルが `Err(Lagged)` を返し、サーバーがこれを致命的エラーとして切断していたため。

**適用された修正 (`581daf4f`):**
- サーバー側: `Lagged` エラー発生時は切断せず `continue` でフレームをスキップするよう変更
- サーバー側: Caddy プロキシ等のタイムアウトを防ぐため 30秒の ping/pong キープアライブを追加

## 6. OTA アップデートが 59% でクラッシュする

**症状:** `/api/v1/firmware/download` 経由の OTA アップデートが約 59% で `StoreProhibited` エラーを発生させてクラッシュする。

**根本原因:** Core 1 上で NimBLE BLE 広告/スキャンと HTTP クライアントが同時に動作し、スタック領域が不足したため。

**修正方法:**
1. `esp_https_ota_begin()` を呼び出す前に NimBLE スキャンを停止する
2. httpd スタックサイズを 4KB から 8KB へ拡張する
3. OTA 完了後に BLE を再開する

旧ファームウェア（0.8.0未満）のノードは、初回のみ USB 経由で新ファームウェアを書き込む必要があります。

## 7. LAN 経由で babycube に SSH 接続できない

**症状:** `ssh thyhack@10.0.10.10` がバナー交換でハングする。

**回避策:** Tailscale IP を使用して接続します：
```bash
ssh thyhack@100.90.238.87
```

## 8. 一部の ESP32-S3 基板で右側 USB-C ポートが動作しない

**症状:** 基板の右側 USB-C ポート（ポートが自分に向いている状態）に接続してもシリアルデバイスとして認識されない。

**修正方法:** 左側の USB-C ポートを使用してください。多くの ESP32-S3-DevKitC 基板において、左側ポートが書き込みおよびシリアル通信用の USB-to-UART ブリッジ（CP2102/CH340）となっています。右側はネイティブ USB（USB-JTAG）ポートです。

## 9. Windows 上の Docker Desktop が複数 ESP32 ノードの UDP をドロップする

**症状:** 複数の ESP32 ノードから送信されている UDP データグラムが、Windows 上の Docker Desktop 内のコンテナに 1 つの送信元 IP からしか届かない。

**根本原因:** Docker Desktop on Windows の Hyper-V / WSL2 ネットワーク転送における制限（`vpnkit` の仕様）。

**修正方法:** ホスト上で転送リレープロセッサを実行します：

```powershell
# 1. リレースクリプトの開始
python scripts/udp-relay.py --listen-port 5005 --forward-port 5006

# 2. docker/docker-compose.yml の UDP ポートマッピングを 5006:5005/udp に変更
# 3. コンテナを再起動
docker compose -f docker/docker-compose.yml up
```

## 10. sensing-server 実行時に可視化ページで `404` エラーが発生する

**症状:** `sensing-server` を起動後、`http://localhost:3000/` にアクセスすると `404 Not Found` になる。

**根本原因:** デフォルトの `--ui-path ../../ui` がバイナリの位置ではなく、コマンドを実行した「カレント作業ディレクトリ」からの相対パスとして解釈されるため。

**修正方法:** 絶対パスを指定するか、クレートディレクトリから実行します：

```bash
# 方法 A — 絶対パスの指定（推奨）
sensing-server --source esp32 --udp-port 5005 --http-port 3000 \
  --ws-port 3001 --ui-path /absolute/path/to/ui

# 方法 B — クレートディレクトリから実行
cd v2/crates/wifi-densepose-sensing-server
cargo run -- --source esp32
```

## 11. `--edge-tier 1` または `--edge-tier 2` でブートループが発生する

**症状:** `--edge-tier 0` では正常起動するファームウェアが、`1` や `2` では再起動を繰り返す。

**根本原因:** エッジティア 1 / 2 で有効化される Core 1 上のオンデバイス DSP タスクが FreeRTOS ウォッチドッグにイールド（処理を譲る）していなかったため。

**修正方法:** リリース版 [v0.4.3.1-esp32](https://github.com/ruvnet/RuView/releases/tag/v0.4.3.1-esp32) 以降に更新してください。タスクイールドの修正が含まれています。
